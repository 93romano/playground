# 네트워크 로우지식 정리 — 주소창에서 첫 바이트까지

프론트엔드 엔지니어를 위한 네트워크 학습 모듈. 브라우저 `fetch` 한 줄 아래에서 실제로 벌어지는 일 — 패킷, TCP, DNS, TLS, HTTP의 진화 — 을 "왜 그렇게 설계됐는가" 중심으로 파인만 학습법에 맞춰 한국어로 정리한다.

학습 로드맵의 **3단계**다: 1단계(컴퓨터 구조) → 2단계(OS) → **3단계(네트워크)**.

---

## 핵심 질문

> **주소창에 엔터를 치면, 첫 바이트가 도착하기까지 무슨 일이 일어나는가?**

이 한 질문을 여섯 조각으로 쪼갠 것이 이 모듈이다:

```
엔터!
 │
 ├─ ① 이름을 숫자로: www.site.com → 203.0.113.9        [03 DNS]
 ├─ ② 연결 열기: SYN → SYN·ACK → ACK (1 RTT)            [02 TCP]
 ├─ ③ 비밀 채널: TLS 핸드셰이크 (1 RTT)                  [04 TLS]
 ├─ ④ 요청 싣기: GET / — 어떤 판(h1/h2/h3)에 실을까      [05 HTTP]
 ├─ ⑤ 패킷의 여행: 1460B 조각들이 홉을 건너            [01 IP/라우팅]
 └─ ⑥ 첫 바이트 도착 — 그리고 이걸 빠르게 만들기        [06 웹 성능]
```

## 선수 지식

| 단계 | 모듈 | 이 모듈과의 연결 고리 |
|------|------|---------------------|
| 1단계 | [컴퓨터 구조](../claude/README.md) | 캐시 계층 ↔ DNS/CDN 캐시, 파이프라인 ↔ 슬라이딩 윈도우·워터폴, DMA/인터럽트 ↔ 패킷 수신 |
| 2단계 | [OS](../os/README.md) | 소켓 = fd, epoll/kqueue ↔ 연결 감시, 커널 버퍼 ↔ TCP 윈도우 |

> 2단계(OS) 모듈은 동시 작성 중이다. 링크가 아직 비어 있어도 이 모듈은 독립적으로 읽을 수 있고, 각 문서의 "이전 계층과의 연결" 절이 접점을 표시해 둔다.

## 문서 목록 (읽는 순서)

패킷(원자)에서 시작해 위로 쌓아 올린다. 01→06 순서를 권장한다.

| # | 주제 | 한 줄 요약 |
|---|------|-----------|
| [01](topics/01-ip-and-routing.md) | 패킷의 여행 — IP·라우팅·NAT | 1500B 패킷이라는 원자, 홉 단위 릴레이, best-effort라는 설계 철학 |
| [02](topics/02-tcp-and-udp.md) | TCP와 UDP | 3-way 핸드셰이크, seq/ACK 재전송, slow start, 그리고 HOL이라는 비용 |
| [03](topics/03-dns.md) | DNS | 재귀·반복 질의, 브라우저→OS→리졸버 캐시 계층과 TTL, prefetch |
| [04](topics/04-tls.md) | TLS | 인증서 체인의 신뢰 위임, 비대칭+대칭 조합, 1-RTT/0-RTT, HTTPS가 강제하는 것 |
| [05](topics/05-http-evolution.md) | HTTP의 진화 | 1.1(6연결·샤딩) → 2(멀티플렉싱) → 3(QUIC) — 왕복 횟수와의 3연전 |
| [06](topics/06-web-performance.md) | 웹 성능 (FE 실무 총정리) | 캐싱 헤더·CDN·preconnect/preload·RTT vs 대역폭·워터폴 읽기 |

각 문서는 동일한 파인만 구조다:

1. **핵심 질문 1개** — 이 문서가 답하는 단 하나의 질문
2. **TL;DR** — 5줄 이내 요약
3. **원자 분해** — 개념을 더 못 쪼갤 단위까지 쪼갠 트리
4. **본문** — 소제목 하나당 원자 하나, 도식 포함
5. **프론트엔드에서 이렇게 만난다** — fetch·DevTools·Lighthouse로 연결
6. **이전 계층과의 연결** — 1·2단계 개념과의 접점
7. **파인만 체크** — 10살에게 말로 설명하는 과제 3개

## 학습 루틴 (파인만 루프)

문서당 한 사이클, 사이클당 30~60분을 권장한다.

```
① 읽기        문서를 처음부터 끝까지. 멈추지 말고 한 번에.
② 원자 분해    책을 덮고, "원자 분해" 트리를 백지에 다시 그린다.
      │        못 그린 가지 = 아직 내 것이 아닌 개념.
③ 소리 내어    파인만 체크 3개를 실제로 말로 설명한다 (10살 상대라 가정).
   설명        전문용어가 튀어나오면 실패 — 비유로 바꿔 다시.
④ 빈틈 재학습  ②③에서 막힌 부분만 본문으로 돌아가 다시 읽는다.
⑤ 한 장 그림   문서 전체를 그림 1장으로 압축해 그린다.
      │        (예: 01은 패킷의 여정도, 04는 핸드셰이크 타임라인)
      └──▶ 다음 문서로. 06까지 끝나면: "엔터→첫 바이트" 전체를
           백지 한 장에 그려내는 것이 이 모듈의 졸업 시험.
```

## 빠른 참조

### 지연시간 감각 (이 모듈의 상수표)

| 항목 | 값 | 비고 |
|------|-----|------|
| 같은 도시 RTT | 5~15 ms | CDN 엣지가 노리는 거리 |
| 서울 ↔ 미국 동부 RTT | 150~200 ms | 광속 하한 ~70ms + 홉/큐 |
| DNS 조회 (cold / warm) | 20~120 ms / ~0 ms | 캐시 계층 덕분 |
| TCP 핸드셰이크 | 1 RTT | 데이터 전 필수 왕복 |
| TLS 1.3 / 1.2 핸드셰이크 | 1 RTT / 2 RTT | 0-RTT 재개 시 0 |
| QUIC(h3) 핸드셰이크 | 1 RTT (TLS 포함) | TCP+TLS 통합 |
| cold HTTPS 첫 바이트 (h2) | ≥ 2 RTT + 서버 처리 | preconnect가 지우는 값 |

### 크기 감각

| 항목 | 값 |
|------|-----|
| 이더넷 MTU | 1500 B |
| MSS (실 데이터/패킷) | 1460 B |
| IP / TCP / UDP 헤더 | 20 / 20 / 8 B |
| TCP 초기 혼잡 윈도우 | 10 MSS ≈ 14 KB (첫 왕복 상한) |
| 요청 헤더 (압축 전) | 0.5~수 KB (쿠키 포함 시) |

### 디버깅 도구 한 줄씩

```
dig +trace example.com        # DNS 위임 사슬 눈으로 보기 (03)
traceroute example.com        # 홉 경로와 구간별 지연 (01)
openssl s_client -connect example.com:443 -showcerts   # 인증서 체인 (04)
curl -w '%{time_namelookup} %{time_connect} %{time_appconnect} %{time_starttransfer}\n' -o /dev/null -s https://example.com
                              # DNS/TCP/TLS/TTFB 구간 측정 (06)
DevTools Network → Protocol 열, Timing 탭   # h2/h3 확인, 워터폴 (05, 06)
```

- 모든 문서는 파인만 구조(핵심 질문 → 원자 분해 → … → 파인만 체크)를 따른다
