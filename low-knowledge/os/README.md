# 운영체제 로우지식 — 하드웨어와 브라우저를 잇는 다리

컴퓨터 구조(claude 모듈)가 "실리콘이 어떻게 동작하는가"를 다뤘다면, 이 모듈은 그 위에서 **커널이 어떤 정책과 추상화로 하드웨어를 프로그램에게 빌려주는가**를 다룬다. 프론트엔드 웹 엔지니어가 매일 만나는 현상 — 탭 크래시, Node 서버의 동시성, Vite의 파일 감시, 컨테이너 OOM — 의 뿌리를 커널까지 내려가 **파인만 학습법**으로 재구성한다.

> 파인만 학습법: "쉬운 말로 남에게 설명할 수 없으면 이해한 게 아니다." 그래서 각 문서는 개념을 **더 쪼갤 수 없는 원자**까지 분해하고, 그 원자로 현상을 다시 조립한다.

---

## 이 모듈을 관통하는 핵심 질문

> ## 🔑 브라우저 탭 하나가 죽어도, 왜 다른 탭은 멀쩡히 사는가?

이 한 질문의 답을 따라가면 프로세스 격리 → 스케줄링 → 가상 메모리 → 파일/IO → 이벤트 루프가 하나의 줄기로 꿰어진다. 답의 핵심(주소 공간 격리)은 [01장](topics/01-process-and-thread.md)에 있고, 나머지 장은 그 격리된 프로세스가 CPU·메모리·디스크·네트워크를 **어떻게 나눠 쓰는가**로 확장된다.

---

## 로드맵에서의 위치 — 2단계 브리지

```
[1단계] 컴퓨터 구조 (low-knowledge/claude)
        CPU · 캐시 · 가상 메모리(HW) · 인터럽트/DMA
                     │
                     ▼
[2단계] 운영체제 (이 모듈) ★  ← 커널 정책 · 추상화
        프로세스 · 스케줄러 · VM 정책 · fd · epoll
                     │
                     ▼
[3단계+] 브라우저 이벤트 루프 · 네트워크 · DB(engine)
```

이 모듈은 **아래(하드웨어)와 위(브라우저·네트워크·DB) 사이의 통역사**다. 그래서 각 문서는 아래로는 claude 문서를, 위로는 이후 단계(브라우저 4단계, DB engine 6단계)를 명시적으로 링크한다.

## 각 문서의 구조 (파인만 5단)

모든 문서가 같은 뼈대라, 원하는 깊이만 골라 읽을 수 있다.

1. **핵심 질문 1개** — 이 문서가 답하는 단 하나의 "왜?"
2. **TL;DR (5줄)** — 답의 요지
3. **원자 분해 트리** — 개념을 더 쪼갤 수 없는 단위로 해체
4. **본문** — 소제목 하나당 원자 하나 + 도식(mermaid/ASCII/SVG)
5. **프론트엔드에서 이렇게 만난다 → 이전 계층과의 연결 → 파인만 체크 3개**

---

## 파인만 학습 루틴 (권장)

각 문서를 이렇게 소화하면 "설명할 수 있는" 수준에 도달한다.

1. **핵심 질문만 보고 스스로 답해보기.** 막히는 지점이 곧 당신의 지식 구멍이다.
2. **원자 분해 트리를 백지에 다시 그리기.** 각 노드를 한 문장으로 설명. 못 하면 그 절 본문으로.
3. **도식을 말로 옮기기.** 화살표 하나하나가 "왜" 그 방향인지 소리 내어 설명.
4. **프론트엔드 사례를 자기 프로젝트로 바꿔보기.** "우리 서버가 느렸던 그때가 이거였나?"
5. **파인만 체크 3개를 후배에게 설명하듯 답하기.** 세 개 다 막힘없이 되면 다음 문서로.

> 막히면 부끄러워 말고 아래 계층으로 내려가라. OS가 안 풀리면 대개 claude(하드웨어)에 답이 있다. 이 모듈은 그 사다리다.
