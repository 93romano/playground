# low-knowledge — 이론 계층 서고

컴퓨터를 밑바닥부터 이해하기 위한 **이론 계층(theory layer)** 문서 모음이다. [마스터 로드맵](../README.md)의 1~4단계에 해당하며, "매일 쓰지만 속을 모르는" 계층 — CPU, 운영체제, 네트워크, 브라우저 — 을 아래에서 위로 한 층씩 열어본다. 모든 문서는 한국어 본문 + 영어 용어 병기, "왜 그렇게 설계되었는가"를 중심으로 서술한다.

> 이 서고의 목표는 위층 실전(5~7단계: [데이터 계층](../redis-postgresql-nodejs/) · [DB 엔진](../engine/) · [설계 패턴](../design-patters/1/))을 배울 때 **마법 상자가 하나도 남지 않게** 하는 것이다.

---

## 권장 학습 순서

아래층의 원자가 위층의 전제가 되므로, **위에서 아래 순서대로** 읽는 것을 권한다.

```
claude (컴퓨터 구조) → os (운영체제) → network (네트워크) → browser (브라우저·JS 런타임)
        1단계                2단계              3단계                    4단계
```

### 1. [`claude/`](claude/) — 컴퓨터 구조 ✅

> 코드 한 줄이 실행될 때 CPU와 메모리에서 무슨 일이 일어나는가?

CPU와 메모리가 실제로 어떻게 동작하는지를 다루는 **12편**의 문서. 수 표현(2의 보수·IEEE 754)에서 시작해 ISA, 파이프라인, 캐시, 가상 메모리, 멀티코어 일관성, SIMD, 성능 튜닝, 사이드채널까지 이어진다. 각 문서는 *TL;DR → 기초(면접/CS) → 심화(마이크로아키텍쳐) → 실무 성능 → 추가 키워드*의 5단 구조라 원하는 깊이만 골라 읽을 수 있다.

- **시작:** [claude/README.md](claude/README.md)의 학습 로드맵
- **원자:** 2의 보수·IEEE 754 / ISA·명령어 사이클 / 파이프라인·해저드 / 캐시·지역성 / 메모리 계층
- **위층 연계:** [07 가상 메모리](claude/topics/07-virtual-memory.md)·[09 I/O와 인터럽트](claude/topics/09-io-and-interrupts.md)는 2단계(운영체제)의 직접적인 밑바탕이 된다.

### 2. [`os/`](os/) — 운영체제 🆕

> 브라우저 탭 하나가 죽어도 다른 탭이 사는 이유는?

프로세스 격리부터 이벤트 루프의 밑바닥까지, "왜 Node는 스레드 하나로 수만 연결을 버티는가"에 답하는 모듈. 1단계의 가상 메모리·인터럽트 지식을 그대로 이어받는다.

- **원자:** 프로세스 vs 스레드 / 컨텍스트 스위치 / 스케줄링 / 가상 메모리 / 시스템 콜 / 파일 디스크립터·페이지 캐시 / 블로킹 vs 논블로킹·epoll

---

### 3. [`network/`](network/) — 네트워크 🆕

> 주소창에 엔터를 치면 첫 바이트가 도착하기까지 무슨 일이?

DNS 조회에서 TLS 핸드셰이크, HTTP/3(QUIC)까지 한 요청의 전 생애를 추적하는 모듈. "지연시간의 사다리"에서 네트워크 왕복(RTT)이 왜 가장 비싼 칸인지를 몸으로 이해하게 된다.

- **원자:** IP·포트·라우팅 / TCP 핸드셰이크·재전송·혼잡제어 / DNS 재귀·TTL / TLS 핸드셰이크 / HTTP/1.1 → 2 → 3(QUIC) / 캐싱 헤더·CDN

---

### 4. [`browser/`](browser/) — 브라우저 & JS 런타임 🆕

> 내 JS 한 줄이 화면의 픽셀이 되기까지?

프론트엔드 엔지니어의 **코어 모듈.** V8이 JS를 어떻게 실행하고, 이벤트 루프가 어떻게 돌며, DOM이 어떻게 픽셀이 되는지를 다룬다. 앞의 세 모듈(구조·OS·네트워크)이 모두 여기서 한 번에 회수된다.

- **원자:** V8 파싱 → 바이트코드 → JIT / 히든 클래스·인라인 캐시 / 힙·세대별 GC / 이벤트 루프(태스크·마이크로태스크·rAF) / 렌더링 파이프라인(DOM → CSSOM → 레이아웃 → 페인트 → 컴포짓) / 브라우저 프로세스·스레드 모델 / Core Web Vitals
